# 关于系统

从 `关于人/` 那些想法里落下来的、**可迁移的工程判据**。

## 收录标准

**只收不随开发变的东西。**

具体代码架构 —— 模块名、字段名、当前的实现选择 —— **一律不收**。
理由很简单：**它们还在变，写进来看的人会当成已定论，等于误导。**

所以这里每一条的形态是「**一个判据 ＋ 它排除了哪些"看着像对"的做法**」，
而不是「我们是怎么实现的」。

## 目录

| 文件 | 一句话 |
|---|---|
| `01-不要搬进工程的四件事.md` | 四种"看着像理论落地、其实是坑"的做法 |
| `02-外部反馈不能替代内部可验证标准.md` | 能被独立核验的事实，不该由"谁说的"决定 |
| `03-成功声明必须与执行结果绑定.md` | 拿不到结果就说"未完成＋原因" |
| `04-内部监测与能力形成.md` | 没有内部监测，就不会形成稳定的能力模型 |
| `05-过度泛化与它的消退.md` | 规则没错，边界错了；以及怎么让它自净 |

> 这些摘自一份更长的、把理论映射到某个具体项目的交流记录。
> 那份记录里**含具体实现**，未公开；这里只留了**不随开发变**的部分。
